# Claude Board: end-to-end UX and QA review (2026-11-10)

Reviewed: commit `91389a3` ("Polish the web UI…"), exported to a scratch folder and run from there. The working tree was being changed by other work (multi-board feature, README, join, doctor) during the review, so **uncommitted changes were not reviewed**. Screenshots: `a local scratch folder` (file names below). Terminal transcripts: `…\ux-review\transcripts\`. Agent `next_action` logs: `…\ux-review\p3-next-actions.txt`, `p5-log.txt`.

Severity: **Blocker** (stops the day) · **Major** (real harm or confusion that a team will hit) · **Minor** (friction, fixable workaround) · **Polish**.
Type: bug · usability · copy · visual · missing feature · a11y · docs.

## Summary

**Overall impression.** Claude Board is in good shape. The happy path works: start the board, set the goal, join, start agents, plan, build, review, merge. The web board explains itself well. Almost every control has a tooltip, empty states say what happens next, and the visual design is calm and consistent in both light and dark mode. Keyboard support is solid, and live updates are fast (about 200 ms from an agent post to the feed) even with 18 agents and 120 tasks. Nothing I found would stop a hackathon day.

The weak spots are at the edges, and they are exactly the edges that hurt a team in a hurry:

- **Join and doctor** report "All good" or exit 0 when they haven't really succeeded. They also give the wrong cause after a token rotation, and they miss name clashes.
- **The web board lets a human put the board into states the agents can't recover from.** Moving a card to Claimed or In progress leaves it with no owner and skips its dependencies.
- **The single "What to do now" line hides the most important action.** One agent question outranks plan approval, which blocks every agent.
- **Agents get contradictory or wrong guidance in a few states:** blocked tasks, a self-reported usage limit, and a duplicate name on two laptops.
- **The layout doesn't scale to a busy day.** Columns grow without limit, the board starts below the fold at 1366×768, and the presenter view overflows.

**Counts:** 0 Blocker · 16 Major · 56 Minor · 20 Polish (92 findings).

### Top 10 improvements (in priority order)
1. **WB-13 Moving a card by hand creates tasks nobody can pick up.** Move… or drag to *Claimed* or *In progress* leaves the task with no owner and ignores *waits on*. Ask who it's for, or move it to Open instead.
2. **AG-6 / JOIN-4 Two laptops can share one agent name.**
   - The second laptop's agent is handed the first one's tasks, with no warning.
   - Join only spots a clash if the other agent has already connected.
   - Tell the agent in `next_action`, and check names that join has registered too.
3. **JOIN-1 / JOIN-2 / JOIN-3 Join "succeeds" when it didn't.**
   - It keeps going against an unreachable or misspelled board, and against https on an http board.
   - It writes broken configs and exits 0.
   - After a failed Copilot-in-VS-Code setup, it checks Claude Code instead.
   - Stop early, normalise the URL, check the tool the user actually picked, and exit non-zero.
4. **WB-3 "What to do now" should rank by how much is blocked.** Plan approval and picking who merges (which block the whole team) are hidden behind any open question. Show the top 2–3 items, ranked by how many agents each one blocks.
5. **ER-2 / JOIN-14 / AG-7 Token rotation strands everyone with the wrong explanation.**
   - Doctor says "the host started a fresh board".
   - The web page says "token was rejected".
   - Agents get "bad or missing token".
   - Say "the host rotated the token; re-run join", and give the steps.
6. **WB-14 The board doesn't scale.** Cap the Open column (show 15, then "show N more"), or let columns scroll. On a busy 1366×768 screen the task columns start below the fold.
7. **AG-1 / AG-5 Fix contradictory `next_action` texts.**
   - An agent with a blocked task is told both "keep them moving before claiming more" and "claim #9".
   - An agent that reported its own usage limit is told "a human marked you… this call clears the mark".
8. **ONB-2 The demo time is hard to find.** It hides inside step 2 and disappears when the goal is saved. The freeze, reminders and wrap-up all depend on it, so make it its own step (or ask for it next to the goal).
9. **ONB-6 / ONB-5 One consistent set of start commands and supported tools everywhere.**
   - The Copilot CLI command on the board and in the invite drops `--autopilot …`.
   - The gate, the intro, the help and the playbook list only Claude Code, Codex and Copilot. Gemini CLI and Cursor are missing.
10. **WB-6 / PV-3 Show who is really online and working.**
    - "6 agents online" counts agents that are offline or out of usage.
    - The presenter shows "working (last board call: update_task)" and leaves out agents that hold tasks.

### Quick wins (small effort, big effect)
- Make join exit non-zero when doctor finds problems. Add `http://` when the scheme is missing. Recognise the SSL version error as "this board is http, not https" (JOIN-1, JOIN-2).
- Change doctor's 401 message to "the token changed (rotated, or a fresh board)…" (JOIN-14). Make the web gate say the same (ER-2).
- Copy fixes:
  - AG-5: self-reported usage limit.
  - AG-1: blocked tasks don't count against slots.
  - PV-3: the presenter's `last board call: update_task` text.
  - Copilot CLI start command everywhere (ONB-6).
  - Add Gemini CLI and Cursor to every "Claude Code, Codex or Copilot" sentence (ONB-5).
- Join: don't ask the plan question for Codex or Copilot, since every option means 1 task (JOIN-6). Re-ask on an unknown tool instead of exiting (JOIN-5).
- Doctor for `other`: print the MCP URL again (JOIN-9).
- Make the "disconnected" bar sticky under the header (ER-1).
- Presenter: strip markdown from the goal, and fit 1366×768 (PV-1, PV-4).
- Retro: count tasks that are still blocked (NO-2).

## Findings by area

### 1. Onboarding and setup (host)

**ONB-1 · Minor · copy**: The startup banner leaves out two things a host needs on day one.
- *Did:* `npm start` (`banner.txt`).
- *Saw:* Two numbered steps, the link and the join command. Nothing says the token in the link is a password. Nothing says to use `npm run tunnel` when teammates aren't on the same wifi (that only appears when no address is found). `npm run doctor` isn't mentioned.
- *Why it matters:* The host often pastes this whole block into a public channel, and the first "it doesn't connect" happens at the venue.
- *Suggest:* Add one line: "The token is the board's password: share it only with your team. Teammates on another network? Stop and run `npm run tunnel`."

**ONB-2 · Major · usability**: The demo time is easy to miss.
- *Did:* Opened step 2, saved the goal.
- *Saw:* Step 2 collapsed straight away and the "Demo time" form went with it (`07-goal-saved.png`). The step showed a ✓ and only the goal text. The header clock appears only once a time is set. `07b-goal-step-reopened.png` shows the form is still inside the done step.
- *Why it matters:* The feature freeze, the 30-minute warning, the wrap-up and the presenter countdown all depend on it. A host who doesn't reopen a ✓ step never sets it.
- *Suggest:* Make "Demo time" its own step, or keep step 2 open until the time is saved or skipped. Add a now-strip hint ("Set the demo time so agents stop on time") once the goal is set.

**ONB-3 · Minor · usability**: "Rotate token…" sits inside step 1, between the invite instructions and the notifications.
- *Saw:* `04-first-board.png`.
- *Why it matters:* It is a destructive action in the middle of the "invite people" flow, the place most clicked in the first ten minutes. It is behind a confirm, but the placement says "part of setup".
- *Suggest:* Move it to a "Security / board settings" area (or the "you:" menu). Keep a short link from step 1.

**ONB-4 · Minor · usability**: On first load, step 1 fills the whole viewport.
- *Saw:* At 1440×900 the steps for the goal, the agents and who merges are below the fold (`04-first-board.png`, `04b-first-board-full.png`).
- *Why it matters:* The host can usually set the goal and the demo time while teammates are still cloning, but the page guides them to "Connect your first laptop" first.
- *Suggest:* Collapse the "other addresses / QR / watch link / notifications / rotate" sub-parts by default. Or say in the now strip that setting the goal can happen in parallel.

**ONB-5 · Minor · copy**: The supported tools are listed inconsistently.
- *Where:*
  - Gate lede (`01-gate-no-token.png`): "Claude Code, Codex or GitHub Copilot".
  - Start here intro (`04-first-board.png`): same.
  - Help → "Agent (and which tool)": same.
  - `templates/playbook.md` intro: "Claude Code, Codex or GitHub Copilot".
  - `package.json` description: same.
- *Why it matters:* Gemini CLI and Cursor users wonder if they're supported, even though step 3 and join support them.
- *Suggest:* One shared phrase, e.g. "Claude Code, Codex, Copilot, Gemini CLI or Cursor (or any MCP tool)".

**ONB-6 · Major · copy/bug**: The Copilot CLI start command differs by place.
- *Where:*
  - README, join, doctor and the server's `AGENT_TOOLS` say `copilot --allow-tool board --autopilot --max-autopilot-continues 50`.
  - Start here step 3 shows only `copilot --allow-tool board`: the regex in `stepStart` cuts it (`09-steps-345.png`).
  - The invite message says "start it with  copilot --allow-tool board  then type /board".
- *Why it matters:* Without `--autopilot`, Copilot CLI stops after a few steps. The README itself notes Copilot "stops more often", and the invite is what most teammates actually read.
- *Suggest:* Use the full command in step 3 and in `inviteText()`. Take it from one source (`AGENT_TOOLS`).

**ONB-7 · Minor · usability**: The invite message and the QR codes don't fit how people actually work.
- *Saw:*
  - The invite (clipboard text, see `p2` log) has a tool note only for Codex and Copilot CLI. Gemini and Cursor are missing.
  - The second QR's caption says "Join command: scan, then paste it in the claude-board folder". A phone can't paste into the laptop's terminal.
- *Suggest:*
  - Drop the join-command QR, or replace it with a QR of the board link opened at "Connect your laptop".
  - Add the missing tools to the invite.

**ONB-8 · Minor · usability/copy**: Names are changed without telling the user.
- *Did:* Typed "Host Person" at the gate.
- *Saw:* The page signed in as `hostperson` with no notice (p1 log). Join behaves the same way (`replace(/[^\w.-]/g,'')`).
- *Why it matters:* People then don't recognise their own @mentions, or they pick a second name.
- *Suggest:* Show "You'll appear as hostperson" under the field as they type. Or turn spaces into `-`.

**ONB-9 · Polish · visual**: The header wraps to two rows once a demo time is set.
- *Saw:* At 1440 px, "Show / + New task / Presenter view / Copy link / bell / you / ?" drop to a second row (`08-deadline-set.png`; also at 1366, `64-1366.png`).
- *Why it matters:* The layout jumps the moment the clock appears, and the header grows to about 96 px.
- *Suggest:* Hide the tagline when space is short. Collapse "Presenter view" and "Copy link" to icons. Or move the clock into the now strip.

**ONB-10 · Minor · copy**: Time formats differ across the product.
- *Saw:*
  - Header: "freeze 03:25 AM".
  - Feed: "set the demo deadline to 11/10/2026, 4:25:00 AM" (`09-steps-345.png`).
  - Summary: "11/10/2026, 2:23:01 AM – …".
  - Help: "by default 60 minutes".
- *Suggest:* Use one formatter: "Tue 16:00" or "4:00 PM", no seconds and no full date unless it's another day.

**ONB-11 · Minor · usability**: The host-join prompt defaults to Yes, and "No" is remembered for that data folder.
- *Did:* Ran the server in a pty and answered `n` (`host-decline` transcript), then started a second board and pressed Enter (`host-accept`).
- *Saw:* Pressing Enter started the full join questionnaire in the middle of the server output. "n" writes `data/.host-join-declined`, and the prompt never comes back. The repeated links after join are good.
- *Suggest:* Fine as is. Consider "[y/N]" when stdin is a TTY but the user has already joined another board. Print "Run `npm run join -- …` any time" whenever the prompt is suppressed, not only on decline.

**ONB-12 · Polish · usability**: `npm run rehearse -- --dry-run` ends confusingly.
- *Saw:* It prints `board: http://localhost:57038/?token=…` (a board that has already stopped), then "Dry run: stopping here. The temp folder is kept." It leaves `%TEMP%\claude-board-rehearsal-*` behind.
- *Suggest:* In a dry run, say "the board would run at …" and delete the temp folder unless `--keep` is passed.

### 2. Joining (teammate)

All runs used a sandboxed HOME/USERPROFILE/APPDATA, a fake `claude` and `codex` on PATH, and a temp repo with a local bare origin. Transcripts are in `transcripts/j*.txt` and `d*.txt`.

**JOIN-1 · Major · bug/usability**: Join goes all the way through against a board it can't reach, and exits 0.
- *Did:* `--url http://localhost:4799` (nothing running there). Also a URL without a scheme, and https (`j5-down`, `j10-wrongurl`, `j11-https`).
- *Saw:*
  - "✗ cannot reach board at http://localhost:4799: fetch failed … Continuing anyway; run npm run doctor later."
  - It then asked every question, ran `claude mcp add` with the dead URL, installed the shortcut, and ended "⚠ 1 problem(s) above…" with **exit 0**.
- *Why it matters:* The user's tools now point at a wrong address. Scripts and CI can't tell it failed, and "Continuing anyway" reads like success.
- *Suggest:* Stop on an unreachable board: "Can't reach … Check the address. Is the host's window open? Then run this again." Allow `--offline` to force it. Always exit 1 when doctor reports problems.

**JOIN-2 · Major · usability/copy**: Easy URL mistakes aren't caught.
- *Saw:*
  - `--url localhost:4712` gives "fetch failed", and a web link `localhost:4712/?token=…` that can't be clicked.
  - `--url https://…` against an http board gives doctor's "(ERR_SSL_WRONG_VERSION_NUMBER) → Is the host's npm start window still open? Same wifi…".
- *Why it matters:* People type addresses by hand from a projector or a phone photo, so these are the most common errors. The advice sends them to check the wifi.
- *Suggest:* Add `http://` when the scheme is missing. Recognise the SSL version error: "This board uses http, not https: try http://…". Strip a trailing `/?token=…` if someone pastes the board link instead.

**JOIN-3 · Major · bug**: Copilot in VS Code with no repo fails, then doctor checks the wrong tool.
- *Did:* `copilot-vscode`, plan `pro`, left the repo blank (`j8-vscode-norepo`).
- *Saw:*
  - "✗ Copilot in VS Code is configured per repo: re-run with --repo …" (it had just asked, and then didn't ask again).
  - Doctor then printed "Claude Code (as "vera") … ✗ Claude Code isn't connected … ✗ the start shortcut is missing (…\.claude\commands\board.md)". Exit 0.
  - Cause: `saveConfig(done)` with no agents makes doctor fall back to `[{tool:'claude'}]`.
- *Why it matters:* A Copilot user is told to fix Claude Code, which they don't use.
- *Suggest:* Ask again when a required repo is left blank. Keep the user's chosen tools in the config even when a setup step fails. Remove the `tool:'claude'` fallback.

**JOIN-4 · Major · bug/usability**: The name-clash warning only works once the other agent has connected.
- *Did:*
  - `homes/alice` joined as "dana" (its agent had not started).
  - From another laptop I joined as "Dana" (`j3-clash`): no warning.
  - After an agent connected as `dana`, the same input warned: "dana" is already on this board (Claude Code)… (`j3b-clash`).
- *Why it matters:* Teammates usually all run join in the first minutes, before anyone types `/board`. The check misses exactly that case. Two people sharing a name then share tasks (see AG-6).
- *Suggest:* On join, register a "reserved" name with its laptop id on the board (a REST call). Check reserved names as well as presence.

**JOIN-5 · Minor · usability**: A typo in the tool list aborts the whole join.
- *Saw:* "claud" gives "✗ Unknown tool(s): claud. Pick from: …" and exit 1, after the name was already answered (`j3b-clash`).
- *Suggest:* Ask again, and suggest the closest tool ("Did you mean claude?").

**JOIN-6 · Minor · usability**: The plan question is pointless for Codex and Copilot.
- *Saw:* "Which plan is Codex CLI on?" with four options, all "→ 1 task at a time" (`j2-bob-multi`, `j14-copilotcli`).
- *Why it matters:* An extra question with no effect, and it implies a choice that doesn't exist.
- *Suggest:* Skip it when every option gives the same number of slots. Record the plan silently if the board needs it.

**JOIN-7 · Minor · copy**: The prompt for the repo path undersells what a blank answer skips, for Claude Code.
- *Saw:* "Path to your copy of the hackathon repo (installs the auto-wake hook there; blank to skip)". A blank answer also skips the pre-approved git/gh commands and board permissions (`settings.local.json`). Those are the reason given in the README ("the merger role moved 6 times…").
- *Suggest:* "(installs the auto-wake hook and pre-approves git/gh there, so agents don't stall on permission prompts; blank to skip)". Default to the current folder's git repo if there is one.

**JOIN-8 · Minor · bug/copy**: "All good" when the tool isn't installed or hasn't been checked.
- *Saw:*
  - Gemini: "• `gemini` is not installed yet…" followed by "✓ Gemini CLI is connected … All good" (`j9-gem-cur`).
  - Copilot CLI: same pattern (`j14`).
  - `other`: "All good" although nothing was verified (`j6-other`).
- *Suggest:* For missing binaries, finish with "Ready once you install X". For `other`, use "Next: add the server shown above to your tool" instead of "All good".

**JOIN-9 · Minor · usability**: Doctor can't show the `other` tool's address again.
- *Saw:* `d4-olga`: "• add the board to your tool yourself: npm run join printed its address (or re-run join with --tool other)". The config has the URL and token.
- *Suggest:* Print the MCP URL (name/type/url) in doctor for `other` agents.

**JOIN-10 · Polish · copy**: Some output lines are walls of jargon.
- *Saw:* "✓ pre-approved git (fetch, switch, checkout, add, commit, push, merge, pull, status, diff, log, worktree, branch, rev-parse, remote) and gh (pr, run, auth status, repo view); force pushes are discouraged, not prevented: protect main on GitHub (README: "Protect main"). Skip with --no-git-allow". The Codex block is similar (`j2`).
- *Suggest:* "✓ git and gh commands pre-approved (no prompts when agents push or merge)". Put the details behind `--verbose`.

**JOIN-11 · Polish · copy**: Small wording and layout problems in join and doctor.
- "⚠ 1 problem(s) above".
- "Use "dana" anyway? (y/N) [N]:" shows the default twice.
- Doctor lines "✓     board answers (23 tools)" have odd spacing after the tick.
- "23 tools" means nothing to a user.
- The "Your MCP tool" label in doctor vs "Another MCP tool" in join.

**JOIN-12 · Minor · usability**: Defaults can be wrong.
- The name defaults to the OS user name ("dana" was suggested on every sandbox laptop).
- Claude's plan defaults to `max5` (2 tasks). A Pro user who presses Enter is over-committed, and the board then shows them as able to hold 2.
- *Suggest:* Default to `git config user.name`, or leave it blank with an example. Make Pro the safe default, or require an answer.

**JOIN-13 · Minor · docs**: `--yes` (non-interactive) works (`j13`) but isn't in the README options table or the usage line.

**JOIN-14 · Major · copy**: After a token rotation, doctor blames a fresh board.
- *Did:* Rotated the token, then ran doctor on a joined laptop (`d5-rotated`).
- *Saw:* "✗ the board rejected the token. → The host started a fresh board. Copy the join command from the web board again and re-run it." Join's 401 message says the same.
- *Suggest:* "The board's token changed (the host rotated it or started a new board). Ask the host for the new join command and run it."

### 3. Web board

#### Header and connection

**WB-1 · Minor · usability**: When the server goes down, a scrolled user hardly notices.
- *Did:* Stopped the server while the page was scrolled down (`72-server-down-16s.png`, `72b-down-scrolled.png`).
- *Saw:* The red "Lost the connection…" bar is `position: static` at the top of the page (`top:-800` when scrolled). Only the small "● Disconnected, retrying…" text in the header shows. Recovery works: the bar hides itself and the status goes back to Live.
- *Suggest:* Make the bar sticky under the header, or tint the whole header.

#### What to do now strip and needs badges

**WB-3 · Major · usability**: The single "What to do now" line hides team-wide blockers.
- *Saw:*
  - With the plan waiting for approval (all 6 agents waiting) and one question open, the strip said only "Answer 1 question: an agent is waiting for you" (`22-plan-written-awaiting-approval.png`). Approval appears only as a lower banner and as "Setup: approve the plan".
  - Later, with a task in Review and nobody picked to merge, the strip again showed only the questions. That nudge appeared only as "Setup: pick merger" (`24b-building-busy-full.png`).
  - During the feature freeze and after the demo time, the strip still said "Answer 1 question" (`p5-log`, `55-freeze`, `56-demo-passed`).
- *Why it matters:* A question blocks one agent, while plan approval blocks everyone.
- *Suggest:*
  - Rank by impact (agents blocked), e.g. approval > who merges (with work in review) > questions > blocked tasks.
  - Or show up to three lines ("1. Approve the plan (6 agents waiting) · 2. Answer 1 question · 3. Pick who merges").
  - Show the freeze or wrap-up as a second line.

**WB-4 · Minor · usability**: There is no "after the event" state.
- *Saw:* On the real Kubecon board 9 h after the demo, the strip reads "1 task is blocked: read why and help →", the phase track shows "Build", and the needs badges show "2 new mentions · 1 blocked · 1 stale" (`80-kube-1440.png`).
- *Suggest:* Once the demo time has passed and no agent is online, say "The event is over. Download the summary and retro." Mute urgent styling.

**WB-5 · Minor · usability**: "Same name on two laptops" appears only as a header badge ("ben-claude on 2 laptops", `91-name-two-laptops.png`). The strip still says "1 task is blocked". This is serious enough (see AG-6) to lead the strip.

#### Setup summary bar

**WB-6 · Major · bug/copy**: The online count is wrong.
- *Saw:* "6 agents online · 1 watching" (`50b-stale-offline-full.png`). At that point dave had been offline 25 min (his card says "owner offline — agents may take it over"), and bob-codex and erin were out of usage. The API reported `dave online:false`.
- *Why it matters:* Humans judge capacity from this number. The team really had 3 usable agents.
- *Suggest:* Count only started, online agents that aren't out of usage. Add "· 2 out of usage · 1 offline".

#### People ("Who's doing what")

**WB-7 · Minor · visual/bug**: A person's colour changes when someone else joins.
- *Saw:* hostperson's name and dot were amber with one person (`04`, `08`) and magenta once agents joined (`22`, `24`). Cause: `personHues()` assigns hues in alphabetical order across all known names.
- *Why it matters:* Colour is how people find "their" cards. It shifting mid-session undermines that.
- *Suggest:* Keep each assigned hue (store it on the server, or assign in first-seen order).

**WB-8 · Minor · visual**: Person colours are hard to tell apart beyond about 6 people.
- *Saw:* With 10 people (`90-many-1440.png`), ana/cleo/ben are all blue-teal, dmitri/gus are both green, and eve/farouk/hana are purple-magenta.
- *Suggest:* Add a second channel (initials avatar or pattern), or a palette with larger perceptual distance.

**WB-9 · Minor · usability**: "Belongs to…" hides the agent's own name.
- *Did:* Set dave (an unknown tool, "omp-agent") to belong to carol.
- *Saw:* Carol's row shows "Codex · 0/1 tasks · omp-agent · 1/1 tasks". The word "dave" appears nowhere in the row, and dave vanished from the "Show" filter (`37-bob-limits.png`, `p4-log`). The expanded row says "@main agent · omp-agent".
- *Suggest:* Show the agent name in the pill when it isn't `<person>-<tool>` ("dave · omp-agent · 1/1").

**WB-10 · Minor · usability**: Two agents with the same tool look identical.
- *Saw:* Kubecon: emil's row shows "Claude Code · offline · Claude Code · offline · Codex · offline" (`80-kube-1440.png`). There's no way to tell emil-claude from emil-claude2.
- *Suggest:* When a label repeats, add the name suffix ("Claude Code (claude2)").

**WB-11 · Polish · copy**: Odd labels and stale names in the expanded row.
- Agents show as "@main agent · Claude Code" (the "@" looks like a mention).
- Kubecon "Belongs to" lists ghost or near-duplicate people: "finn", "finn0", "milo" (`p8-log`).
- "Last seen 5h ago" in the detail vs "9h ago" in the row for the same agent.

**WB-12 · Polish · visual**: The colour code of the pills isn't explained.
- Green means "has room" and blue means "full" (`24b`). Nothing explains this.
- The "watching" dot is amber in People but green in the Start here chip for the same person (`04b`).
- *Suggest:* Add a legend line or a tooltip, and use one dot colour per state.

#### Columns and cards

**WB-13 · Major · bug**: A manual move creates tasks with no owner and skips dependencies.
- *Did:*
  - Move… → In progress on #3 ("waits on #2").
  - Move… → Claimed on #9 (reserved for carol).
- *Saw:*
  - "#3 moved to In progress (Undo)". The API shows `{status:"in_progress", assignee:null}`, and the card reads "In progress · unassigned · waits on #2" (`34b-after-move.png`).
  - #9 shows "Claimed · unassigned · reserved for carol" (`50b`).
- *Why it matters:* No agent holds these tasks, and no agent can claim them (they're not Open), so they sit forever. They count as "running" in "Team can run 9 tasks at once · 7 running". They also appear as not finished in the summary.
- *Suggest:*
  - Moving to Claimed or In progress should open "Assign to…" (prefilled with the reserved agent).
  - Or limit manual moves to Open / Blocked / Review / Done and warn about unmet dependencies.

**WB-14 · Major · usability/visual**: The board doesn't scale and is below the fold on common screens.
- *Saw:*
  - With 120 tasks, the Open column lists all 84 cards and the page becomes about 10,600 px tall (`90b-many-full.png`). Done collapses, but Open/Claimed don't.
  - At 1366×768 on a normal busy board, the questions, setup bar, people and the demo-passed note push the first card row off screen (`64-1366.png`, `84-kube-1366.png`).
- *Suggest:*
  - Cap each column (e.g. 12 cards, then "Show 72 more"), or make columns scroll within themselves.
  - Let People collapse to one line.
  - Move the "write-up" note into the strip.

**WB-15 · Minor · visual**: The card badges are uneven.
- P1 shows a red "P1", P2 shows nothing, and P3 shows a grey "low". Size S and L get badges but M doesn't.
- Every open card shows "unassigned" (`22b`). Users can't tell "normal" from "unknown", and the repeated "unassigned" is noise.
- *Suggest:* Hide "unassigned" in the Open column (it's implied). Use consistent priority chips (or only flag P1 and "low"), and explain this in the help.

**WB-16 · Minor · a11y**: The PR pill on cards can't be reached by keyboard.
- *Saw:* The PR link has `tabindex="-1"` (`card()` in index.html). Keyboard users can't open the pull request from the board; the dialog doesn't show it either.

### 4. Agent guidance (`next_action`) and playbook

**AG-1 · Major · copy/bug**: `next_action` contradicts itself when the agent holds a blocked task.

## What works well (keep it)
- **Tooltips and empty states everywhere** say what happens next ("No tasks yet. Once the goal is set…", "Nothing to merge.").
- **The invite flow:** one "Copy invite message" with every step, plus copy buttons on each command, QR codes and alternative addresses.
- **Join remembers previous answers** on a re-run (`j7-rerun`). It backs up config files once, keeps token files out of git via `.git/info/exclude`, and ends with an exact "type /board in this folder" line per tool.
- **Doctor**: a clear ✓/✗ list with a fix under each problem, including a dry-run push (`d2`, `d3`).
- **Stale and offline handling on cards**: "owner offline — agents may take it over" with *Release to Open* and *Ping @dave*, versus "erin is still online: ping it first" (`50b`).
- **Proposals:** Approve and Reject… on the card, and the proposer is told.
- **Undo toasts on moves**, two-click delete, and the unsaved-changes guard in the dialog.
- **Live updates keep typed text and focus** (the `patch()` approach). Focus is restored after a re-render.
- **Agent `next_action` for stuck work** is excellent: "Stuck tasks whose owner went offline: #7… release_task one with a note", "No progress for 15+ min on #10 (@erin)… don't take their task", "Sent back from review, fix these first".
- **Read-only presenter token** with good no-token and wrong-token messages.
- **Dark mode** is consistent on desktop, phone and presenter (`63-desktop-dark.png`, `62-phone-dark-full.png`, `63-present-dark.png`). Reduced motion turns animation off.
- **Webhook validation** (https only, except localhost) and a working "Send test".
- **Edit conflict warning** in the task dialog (`70-tabB-conflict.png`).
